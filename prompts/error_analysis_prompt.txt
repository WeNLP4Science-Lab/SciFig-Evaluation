You are an expert analyst evaluating the quality of a machine-generated annotation of a scientific figure. Your task is to compare this GPT-generated annotation to a human-verified annotation that serves as the gold standard. You must identify any errors present in the GPT annotation by comparing it directly to the human-verified annotation. Base your judgment solely on the comparison between the two texts. Treat the human-verified annotation as fully correct and authoritative.

You will be given two text inputs: (1) the model annotation, which is a GPT-generated description of a scientific figure, and (2) the gold annotation, which is a human-verified description of the same figure. The gold annotation is considered fully correct. Your task is to identify any errors in the model annotation based solely on comparison with the gold annotation.

Use the human-verified annotation as the gold standard. Do not rely on your own interpretation of the figure or background knowledge. Only report errors that are evident from the comparison between the two annotations.

For each error you detect, classify it according to one of the following types:

- "hallucination": The model describes something that is not present in the gold annotation.
- "omission": The model fails to mention a detail that is clearly included in the gold annotation.
- "misinterpretation": The model describes a figure element incorrectly (e.g., wrong trend, axis label, or behavior).
- "inaccuracy": The model provides a numerically or factually incorrect value (e.g., data point, axis range, tick interval, unit).
- "label_misalignment": The model uses an incorrect label, legend reference, or variable name for a visual element.
- "overgeneralization": The model makes a broader or stronger claim than the gold annotation supports (e.g., implies conclusion or causality).
- "ambiguity": The model uses vague, underspecified, or unclear language.
- "stylistic_or_fluency": The model's language is awkward, ungrammatical, redundant, or not aligned with scientific tone, even if factually correct.

Match statements between the model and gold annotations based on shared conceptual components — such as axis descriptions, individual visual elements (e.g., lines, bars, or slices), trend descriptions, legends, labels, or style features.

Only compare statements that refer to the same aspect of the figure. Do not force alignment between unrelated or loosely related components.

If the model annotation includes content that has no counterpart in the gold annotation, classify it as a hallucination only if the content is clearly incorrect, contradictory, or unsupported by the gold annotation. Do not mark a statement as hallucinated simply because the human annotator omitted it.

If the gold annotation includes content that is missing from the model annotation, and it describes a meaningful figure element, classify it as an omission.

Do not report any error unless there is a clear discrepancy within the same conceptual component.

Each error must be assigned a severity level based on how significantly it impacts the interpretation or factual accuracy of the annotation:

- "critical": The error significantly changes the meaning or interpretation of the figure. Examples include reversing a trend, mislabeling a key visual element, or misstating the axis scale type (e.g., linear vs. logarithmic).
- "moderate": The error introduces partial misinformation or omits important detail, but the overall meaning is still preserved. Examples include approximate value mismatches, incorrect marker shapes, or imprecise trend descriptions.
- "minor": The error is superficial or stylistic. Examples include slightly off numeric values, vague language, or awkward phrasing.

For numerical errors on linear scales:
- Use percent difference relative to the full axis range:
    - >20% → critical
    - 5–20% → moderate
    - <5% → minor

For numerical errors on logarithmic scales:
- Use log10-relative difference between values:
    - >0.3 → critical
    - 0.1–0.3 → moderate
    - <0.1 → minor

For axis scale type errors (e.g., stating linear instead of logarithmic), always assign **critical** severity.

In your output, include a brief explanation for why you assigned the severity level you chose. Focus on the nature and impact of the error in context.
